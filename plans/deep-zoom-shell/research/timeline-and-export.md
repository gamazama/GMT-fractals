## 1. Verified facts

### 1.1 Data model

`types/animation.ts` — `Track` and `Keyframe`:

```ts
export interface Track {
    id: string;
    type: 'float';          // the only type
    label: string;
    keyframes: Keyframe[];
    color?: string;
    hidden?: boolean;
    locked?: boolean;
    postBehavior?: TrackBehavior;   // 'Hold' | 'Loop' | 'PingPong' | 'Continue' | 'OffsetLoop'
}
export interface AnimationSequence { durationFrames: number; tracks: Record<string, Track>; }
```

A keyframe holds one f64 `value`, a `frame`, and `interpolation: 'Step' | 'Linear' | 'Bezier'` with tangents. There is no track type other than float; `AnimationEngine.scrub` drops anything else (`if (track.type !== 'float') continue;`).

### 1.2 How a track value reaches the app (`engine/AnimationEngine.ts`, `getBinder`)

Order of resolution for a track id:

1. `binderRegistry.lookup(id)` — explicit registration, checked before the cache, so it always wins.
2. `lights.*` / `lighting.light*` legacy mapping.
3. Universal DDFS resolver for `featureId.param`: looks up `featureRegistry.get(parent)`, then the store action `set<FeatureId>` and calls `setter({ [child]: v })`. Vec components use `featureId.param_x` (UNDERSCORE form).
4. Root-level `set<Id>` fallback.
5. Otherwise a silent no-op binder.

Decisive lines:

```ts
const registered = binderRegistry.lookup(id);
if (registered) return registered.write;
...
const setterName = `set${parent.charAt(0).toUpperCase() + parent.slice(1)}`;
...
binder = (v) => setter({ [child]: v });
```

The setter name is generated by `store/createFeatureSlice.ts` (`const actionName = \`set${feat.id.charAt(0).toUpperCase() + feat.id.slice(1)}\``), so the two agree.

**Answer: a feature's scalar parameters are keyframable with no extra code.** `components/AutoFeaturePanel.tsx` takes `keyframes = true` by default and passes `trackId = scalarBinding.trackKeys[0]` to the slider; `hooks/useTrackAnimation.ts` gives the diamond button, the keyed/dirty status and auto-key when `isRecording` is on.

### 1.3 Registering a binder for a value that is not a feature parameter (`engine/animation/binderRegistry.ts`)

```ts
export interface BinderEntry { id: string; write: (v: number) => void; category?: string; label?: string; }
binderRegistry.register(entry): () => void   // returns unregister; same id replaces
```

The file's own header lists "Non-feature globals an app wants to animate" as a use. So **yes, an app can register a binder for any id**, and `scrub` will call it with the interpolated float each frame.

What the binder registration does NOT give you:

- **No UI reads the registry.** `binderRegistry.list()` has zero callers in the tree (grep `binderRegistry\.\(list\|lookup\)` finds only `AnimationEngine.ts`). `category` and `label` are unused. Nothing creates a track for a registered binder; the track must be put into `sequence.tracks` by code (`addTrack(id, label)` + `addKeyframe(trackId, frame, value, interpolation?)`, signatures in `store/animation/types.ts`).
- **Once the track exists it does appear in the track list.** `components/timeline/DopeSheet.tsx` builds rows from `groupTracks(sequence.tracks)`; `utils/groupTracks.ts` shows every track that is not `hidden`. The row label is `sequence.tracks[tid].label` (`components/timeline/TrackRow.tsx`).
- **Grouping is hardcoded.** `utils/groupTracks.ts` `classifyTrackId`: ids starting `camera.` go to group Camera; five literal `julia.*` ids are also routed to Camera; anything unknown lands in **Shading**. Groups are the fixed list `['Camera','Formula','Optics','Lighting','Shading']`.
- **The live-value / dirty check reads the engine store, not the binder.** `utils/timelineUtils.ts` `getLiveValue` resolves `featureId.param` through `featureRegistry.get(parent)` and `store[parent][child]`. A track id that is not backed by a feature slice has no live value there (what it returns for an unknown id is unverified — I did not read past line 125), so the Key Cam button's dirty colour would be wrong for it.

### 1.4 Key Cam (`engine/animation/cameraKeyRegistry.ts`, `components/timeline/TimelineToolbar.tsx` `KeyCamButton`)

- `registerCameraKeyTracks(tracks)` takes `string | { id, hidden? }`. With nothing registered the button is hidden (`if (tracks.length === 0) return null`).
- Pressing it calls `captureCameraKeyFrame(currentFrame)` and emits `FRACTAL_EVENTS.TRACK_FOCUS` for `tracks[0]`.
- `captureCameraKeyFrame` uses the app's function if one was given to `setCameraKeyCaptureFn(fn)`; otherwise the default walker path-resolves each id in `useEngineStore.getState()` and calls `addKeyframe`. One undo snapshot per press. Tracks are created inline with `label: tid` (the label is the raw id).

```ts
export type CameraKeyCaptureFn = (frame: number, tracks: readonly string[], opts?: CameraKeyCaptureOptions) => void;
export function setCameraKeyCaptureFn(fn: CameraKeyCaptureFn): void
```

- The default walker returns early when nothing resolves (`if (resolved.length === 0) return;`). So a camera track whose value is not in the engine store captures **nothing** unless the app registers a capture function.
- Dirty threshold in `KeyCamButton.getStatus` is `Math.abs(timelineVal - currentVal) > 0.001`.

### 1.5 How fluid-toy carries a high-precision centre on the timeline (`fluid-toy/main.tsx`, `engine/animation/cameraPairRegistry.ts`, `engine/animation/logTrackRegistry.ts`)

Five float tracks, all DDFS params on the `julia` feature:

```ts
registerCameraKeyTracks([
    'julia.center_x', 'julia.center_y',
    { id: 'julia.centerLow_x', hidden: true },
    { id: 'julia.centerLow_y', hidden: true },
    'julia.zoom',
]);
registerLogTrack('julia.zoom');
registerCameraPair({
    zoom:   'julia.zoom',
    pan:    ['julia.center_x',    'julia.center_y'],
    panLow: ['julia.centerLow_x', 'julia.centerLow_y'],
});
```

- The centre is a double-double: a hi word and a hidden lo word, two f64 tracks per axis. `evaluatePairedTrack` (called from `AnimationEngine.scrub` before the normal interpolation) lerps the pair as one DD number: `ddSub` → `ddMulD` → `ddAdd`, giving about 1e-32 absolute precision. Progress along a segment is linear in zoom: `(zT − z0) / (z1 − z0)`.
- `julia.zoom` is registered as a log track, so it interpolates in `log(v)`.
- Limits that matter for the 3D deep zoom: this scheme is two f64 words (about 106 bits). The Mandelbulb page positions the camera with BigInt fixed point at `P:256` (path header `{ format:'gmt-mbulb-path', P:256, ... }`, `mandelbulb_deepzoom/index.html` `window.__lastPath`) and reaches 1e-77. **The camera-pair DD scheme cannot carry that position.** This is why the plan of one float `u` plus a side table of exact views is the right shape.

### 1.6 Getting the timeline on screen (`components/TimelineHost.tsx`)

One component, mounted once at the app root (`fluid-toy/FluidToyApp.tsx` and `fractal-toy/FractalToyApp.tsx` both render `<TimelineHost />`). It owns the bottom-left toggle button, lazy-loads `components/Timeline`, and registers the shortcuts `engine.timeline.toggle` (T) and `engine.timeline.toggle-play` (Space; disabled when `store.cameraMode === 'Fly'`, re-enabled while hovering the timeline through scope `timeline-hover`). Prop: `hidden?: boolean`.

Playback: `AnimationEngine.tick(dt)` advances `currentFrame` and calls `scrub`. The file's `@assumption`: `tick` / `scrub` are silent no-ops until `connect(animStore, fractalStore)` has been called through `bindStoreToEngine()`. Where each app calls `bindStoreToEngine` and who calls `tick` per frame was not opened (unverified).

### 1.7 Scrub hooks (`engine/AnimationEngine.ts`)

```ts
animationEngine.registerScrubHook('pre' | 'post', (ctx: ScrubContext) => void): () => void
// ctx: { frame, isPlaying, isRecording, recordCamera, ignoreCamera }
```

Runs before and after the binders on every scrubbed frame. `ignoreCamera = isPlaying && isRecording && recordCamera`; in that state every track whose id starts `camera.` is skipped. Tracks whose id contains `camera.position` or `camera.offset` are always skipped.

### 1.8 A naming trap in interpolation (`engine/AnimationEngine.ts` `interpolate`, `engine/math/AnimationMath.ts`)

```ts
const isRotation = track.id.startsWith('camera.rotation') || track.id.includes('rot') || track.id.includes('phase') || track.id.includes('twist');
```

A track whose id contains `rot`, `phase` or `twist` gets shortest-path angle wrapping (a jump larger than π between two keys is folded by 2π). The page has `phaseTheta` / `phasePhi` and a path keyframe field `rot`. Any DDFS param named with those substrings will be wrapped. For real angles in radians that is the wanted behaviour; for anything else it silently corrupts a tween.

### 1.9 RenderDialog (`engine/plugins/RenderDialog/index.tsx`, `types.ts`)

Install:

```ts
installRenderDialog<TExtra>({ runner, title?, defaults?, showSamplesPerFrame?, showFrameStep?, showBitrate?,
    disableDiskMode?, formatFilter?, canEncode?, resolutionPresets?, startLabel?, isStartDisabled?,
    extraFormFields?, extraInfoRows?, extraWarning?, onMount?, baseSize?, expandedSize?, renderingViewExtra? });
```

It registers through `registerRenderPopup`, not the top bar or the menu: the timeline toolbar's Render button reads `getRenderPopup()` and is hidden when nothing is registered. So **the render dialog is only reachable with the timeline open**. It is a `DraggableWindow` at `z('tool')` with `disableClose={isRendering}` — it follows the owner's surface rules already.

The runner is one async function; the plugin does not loop frames for it:

```ts
export type RenderDialogRunner<TExtra = Record<string, unknown>> = (deps: RenderDialogDeps<TExtra>) => Promise<void>;

interface RenderDialogDeps<TExtra> {
    cfg:   { width, height, formatIndex, bitrate, samplesPerFrame, startFrame, endFrame, frameStep, fps };
    extra: TExtra;                       // app bag, edited by extraFormFields
    flags: { cancelledRef, finishEarlyRef, stoppingRef, startTimeRef };   // MutableRefObjects the runner polls
    status:{ setProgress(0..1), setElapsedTime, setEtaRange, setLastFrameTime, setStatusText, setIsRendering, setIsStopping };
    isDiskMode: boolean;                 // showSaveFilePicker present and not disabled
}
```

The runner owns: the file picker, the encoder, the frame loop, pause (`stoppingRef`), cancel, finish-early, and restoring state. `fluid-toy/components/RenderDialog/exportRunner.ts` `runVideoExport` is the reference to copy (236 lines). Its loop, per output frame:

```ts
const timelineFrame = cfg.startFrame + i * cfg.frameStep;
animationEngine.scrub(timelineFrame);
applyModulationsAt(time, dt);
await yieldToReact();                 // sleep(0): lets store→engine useEffects commit
engine.resetAccumulation();
for (...) { engine.frame(clock); if (engine.getAccumulationCount() >= sampleCap) break; }
encoder.encodeCanvas(canvas, i);
status.setProgress((i + 1) / totalFrames);
```

So what the dialog needs from a renderer per frame is four things: (1) apply the scrubbed state synchronously or awaitably, (2) render at an exact `width × height` with `samplesPerFrame` samples and say when it is done, (3) hand over pixels in a form `VideoFrame` accepts, (4) stop on request. Plus set and restore the output size around the run.

`defaults.endFrame` falls back to `animStore.durationFrames`, `defaults.fps` to `animStore.fps`; the dialog re-clamps the range when the timeline length shrinks.

### 1.10 Encoders (`engine/export/videoEncoder.ts`, `data/constants.ts` `VIDEO_FORMATS`)

`MainThreadEncoder` — WebCodecs `VideoEncoder` + mediabunny muxer, main thread, video only:

```ts
await enc.start({ width, height, fps, bitrate /*Mbps*/, formatIndex }, stream /* WritableStream | null */);
enc.encodeCanvas(canvas /* HTMLCanvasElement | OffscreenCanvas */, frameIndex);
const buf = await enc.finish();   // ArrayBuffer in RAM mode, null when streamed to disk
enc.cancel();
export const canEncodeFormat(formatIndex, width, height, bitrateMbps): Promise<{ ok, reason? }>
```

Formats, by index: 0 MP4 H.264, 1 MP4 H.265, 2 MP4 AV1, 3 WebM VP9, 4 PNG sequence, 5 JPG sequence. `MainThreadEncoder.start` **throws** on 4 and 5 ("image-sequence formats are not supported"), and `canEncodeFormat` reports them as unsupported. Width and height must be even (the runner aligns them). Bitrate is multiplied by `BITRATE_MULTIPLIER * 2.5`. No audio track in this class.

`encodeCanvas` does `new VideoFrame(canvas as CanvasImageSource, …)`; the cast means an `ImageBitmap` works at run time, but the declared parameter type excludes it.

The header says image sequences and multi-pass go through engine-gmt's `WorkerExporter` (not opened — unverified).

It imports `three` and works on `THREE.WebGLRenderTarget` composites, and saves through `FRACTAL_EVENTS.BUCKET_IMAGE`. ### 1.12 What the page offers today (`mandelbulb_deepzoom/index.html`)

| Need | Handle today | Note |
|---|---|---|
| Current exact view | `__dz.getView()` | `cam` as 3 BigInt strings, yaw, pitch, iters, power, phase, light, falloff, color, cscale, surf |
| Jump to a view | `__dz.setView(v)` | sets `orbitDirty`, `accumReset` |
| Record a flight | `__recordToggle()`, `__recording()`, `__lastPath()` | on stop: `assignCinematicTime` then `smoothPath`; embedded mode does not download |
| Path object | `{ format:'gmt-mbulb-path', P:256, fovScale:1.1, frames:[…] }` | each frame is a view plus `t`, `move`, `rot` |
| Place camera on a path by **time** | `__samplePath(data, tau)` → `pathSampleAt` | Catmull-Rom on BigInt deltas; time-parameterised |
| Place camera on a path by **arc length** | none — `sampleArc(ks, arc, s)` and `pathArc(ks)` are internal | this is what play and render use |
| Preview play | `__playPath(data, {fps, frames})`, `__stopPlay()` | applies `easeInOut` itself, drives its own rAF |
| Render a still | `__export(longEdge, samples, tile)` | downloads a PNG; no pixels returned |
| Render a still, no download | `__exportTimed(longEdge, samples, tile)` | returns `{W,H,samples,ms,litFrac,meanLevel}` only — the blob is discarded |
| Render a whole path | `__renderPath(data, {fps, longEdge, samples, tile, frames, smooth})` | loops itself, ZIP(s) of PNGs split at 500 MB, Esc cancels |
| Progress state | `__dz.telemetry()` | `accumN`, `accumMax`, `exporting`, `playing`, `recording`, `pathFrames` |

Two details that bind the design:

- The canvas is created with `preserveDrawingBuffer:false` (`canvas.getContext('webgl2', { antialias:false, preserveDrawingBuffer:false })`). Grabbing the live canvas into a `VideoFrame` from outside the page's own frame callback can read a cleared buffer.
- `__renderPath` does three things per frame that a frame-by-frame handle must also do: `sampleArc(...)`, then `curOrbit = buildRefOrbit(camHP, cam.iters + 2); uploadOrbit(curOrbit)`, then `renderFrameToBlob(..., f === 0 ? 'fresh' : 0.35)` — the last argument blends the light rig from the previous frame, so frames are **order-dependent**.

## 2. Blueprint for the deep-zoom shell

### 2.1 The track: make `u` a DDFS parameter, not a bare binder

Declare a feature whose id is `camera` with a scalar param `u` (range 0..1), so the track id is `camera.u`. Reasons, each from a fact above:

- It is keyframable, undoable and saved with the scene with no code (1.2).
- `getLiveValue` and the default Key Cam walker both find it in the store (1.3, 1.4).
- The id starts with `camera.`, so it lands in the Camera group (1.3) and is skipped while the user flies in record-camera mode (1.7).
- The id contains none of `rot`, `phase`, `twist` (1.8).

fractal-toy already uses a feature with id `camera` (`camera.orbitTheta`, … in `fractal-toy/main.tsx`), so the id is not reserved by `engine/plugins/Camera.ts` (which defines slots, not a feature).

The renderer is driven from the store value, through the host interface, in one of two ways:

```ts
// (a) explicit binder — runs inside scrub, synchronous, no React commit needed
binderRegistry.register({
    id: 'camera.u',
    write: (u) => {
        useEngineStore.getState().setCamera({ u });   // keep the store truthful for dirty checks
        host.placeOnFlight(u);                        // host = the one renderer-facing interface
    },
});

// (b) no binder; a zustand subscription on store.camera.u calls host.placeOnFlight(u)
```

Prefer (b) if the shell also lets the user drag a `u` slider in a panel, because the same path then serves slider, timeline and undo. Use (a) only if the subscription is found to lag a frame. Either way do NOT route it through a React `useEffect`: the fluid-toy runner needs `await yieldToReact()` for exactly that reason (1.9).

Boot registration:

```ts
registerCameraKeyTracks(['camera.u']);
// no registerLogTrack, no registerCameraPair: u is linear and carries no precision
```

### 2.2 The side table

The exact views (BigInt strings, P:256) live outside the timeline, in the scene, as the page's own path object. The timeline never sees them. `u` in [0,1] maps to arc length `u * arc.total` on that table. A flight therefore has:

- `scene.flight = { format:'gmt-mbulb-path', P:256, fovScale, frames:[view…] }` (where this is stored and how it joins scene save/load is another reader's area — unverified here);
- one track `camera.u`.

`utils/PresetLogic.ts` restores the sequence on load (`if (p.sequence) useAnimationStore.getState().setSequence(p.sequence);`); the save side was not opened.

### 2.3 Recording a flight onto the timeline

The engine has no generic "record the camera while playing" driver: `captureCameraKeyFrame` is called per frame only from `engine-gmt/navigation/Navigation.tsx` and `engine-gmt/components/panels/scene_widgets.tsx`. So the shell uses the page's recorder and converts once on stop:

```ts
// on Record stop
host.stopRecording();
const path = host.lastFlight();                       // __lastPath()
scene.setFlight(path);
const anim = useAnimationStore.getState();
anim.snapshot();                                      // one undo entry
const fps = anim.fps;
const lastT = path.frames[path.frames.length - 1].t;  // cinematic seconds, assigned by the page
const N = Math.max(2, Math.round(lastT * fps));       // same rule as __playPath / __renderPath
anim.setDuration(N);
if (!anim.sequence.tracks['camera.u']) anim.addTrack('camera.u', 'Flight position');
anim.addKeyframe('camera.u', 0, 0, 'Bezier');
anim.addKeyframe('camera.u', N, 1, 'Bezier');
```

The page's `easeInOut` (smootherstep) must NOT be applied inside `placeOnFlight`; the ease is now the two Bezier keys on the track, which the user can reshape in the graph editor. Extra `u` keys retime the flight (slow down, hold, reverse) with no change to the views.

Whether `addTrack` and `setDuration` each push their own undo entry was not checked (`cameraKeyRegistry.ts` says `addTrack` snapshots internally) — if they do, build the track inline as `captureCameraKeyFrame` does.

### 2.4 Key Cam

With `camera.u` as a store value the button works out of the box: it keys the current `u` at the playhead (a retiming key). That is the only meaning the default walker can give it.

If Key Cam should instead mean "add the view I am looking at to the flight", register a capture function:

```ts
setCameraKeyCaptureFn((frame, _tracks, opts) => {
    const view = host.getView();
    const u = scene.insertFlightView(view, frame);    // returns the new view's u; re-normalises existing keys
    if (!opts?.skipSnapshot) useAnimationStore.getState().snapshot();
    useAnimationStore.getState().addKeyframe('camera.u', frame, u);
});
```

Inserting a view changes the total arc length, so every existing `u` key shifts unless the table is re-normalised in the same step. That cost is the argument for an alternative unit: let the track value be the fractional **view index** (0 … n−1) instead of normalised arc length. A key at frame f with value i then means "exactly view i at frame f", inserting a view never moves other keys, and the page's time sampler (`pathSampleAt`, index in place of `t`) already interpolates that way. The owner should pick; both fit one float track.

### 2.5 Render dialog runner

Install once at boot, copy the skeleton of `fluid-toy/components/RenderDialog/exportRunner.ts`, and replace the engine calls with host calls:

```ts
installRenderDialog({
    runner: runDeepZoomExport,
    title: 'Render',
    defaults: { samplesPerFrame: 8 },          // page default for a path render
    formatFilter: (f) => !f.imageSequence,     // until gap G5 is closed
});

// inside the loop
const timelineFrame = cfg.startFrame + i * cfg.frameStep;
animationEngine.scrub(timelineFrame);                    // camera.u → host.placeOnFlight(u), synchronous
const frame = await host.renderFrame({                   // gap G2
    width: safeWidth, height: safeHeight,
    samples: cfg.samplesPerFrame,
    rig: i === 0 ? 'fresh' : 0.35,
    signal: abort.signal,
});
encoder.encodeCanvas(frame.canvas, i);                   // or an ImageBitmap, gap G4
```

Encode at `fps: cfg.fps / Math.max(1, cfg.frameStep)` as fluid-toy does. Poll `flags.stoppingRef` between frames for pause; map `flags.cancelledRef` to the abort.

The host interface this area needs (same shape whether backed by iframe handles or by `createDeepZoom(canvas, options)`):

```ts
interface DeepZoomFlightHost {
    getView(): DeepZoomView;
    setView(v: DeepZoomView): void;
    startRecording(): void;
    stopRecording(): void;
    lastFlight(): DeepZoomFlight;
    setFlight(f: DeepZoomFlight | null): void;          // caches the arc table once
    placeOnFlight(u: number): void;                     // arc-length, no built-in ease

                     rig?: 'fresh' | number; signal?: AbortSignal }):
        Promise<{ canvas: HTMLCanvasElement | OffscreenCanvas | ImageBitmap; width: number; height: number }>;
    isBusy(): boolean;                                  // telemetry().exporting
}
```

## 3. Gaps

Engine gaps are stated generically. Renderer gaps are the handles the page is missing.

**G1 — renderer: no handle places the camera by arc length.** `sampleArc` / `pathArc` are internal. Needed: `placeOnFlight(u)` on a path set once. Interim: `__samplePath(path, u * lastT)` — time-parameterised, so speed is uneven between keyframes (the page's own comment calls the result start-stop), and it re-walks the list on every call.

**G2 — renderer: no handle returns the pixels of one export-quality frame.** `__export` downloads, `__exportTimed` discards the blob, `__renderPath` owns the whole loop and the ZIP. Needed: `renderFrame({width,height,samples,tile,rig}) → canvas | ImageBitmap | Blob`, which rebuilds and uploads the reference orbit itself. This is a thin wrapper over the existing `renderFrameToBlob`. Interim: none that is clean. Converging the live view and grabbing the canvas is unsafe because of `preserveDrawingBuffer:false`; `__renderPath(path, {frames})` still works as a standalone "render to ZIP" menu item outside the dialog (register it as a `registerRenderAdjunct({ label, Dialog })` row in the toolbar's overflow menu) until G2 lands.

**G3 — renderer: output size is a long edge, not width × height; cancel is a keypress.** `renderFrameToBlob` takes `longEdge` and uses the canvas aspect; cancel is the internal `cancelRender` flag set by Esc. Needed: explicit even `width`/`height`, and a `cancelRender()` handle or an abort signal. Interim: resize the iframe to the target aspect before the run; dispatch a synthetic Esc keydown into the iframe.

**G4 — engine: `MainThreadEncoder.encodeCanvas` is typed for canvases only.** The body already accepts any `CanvasImageSource`. Generic fix: widen the parameter to `CanvasImageSource` (or add `encodeFrame(source, index)`), so a renderer that returns an `ImageBitmap` or a pre-built `VideoFrame` needs no copy. Interim: draw the bitmap into a shell-owned 2D canvas and pass that (one extra copy per frame).

**G5 — engine: no image-sequence writer outside engine-gmt.** `MainThreadEncoder` throws on PNG/JPG sequence formats and the default `canEncode` rejects them. The page's native output is a PNG sequence, and for deep-zoom work a lossless sequence is the expected master. Generic fix: a main-thread sequence sink in `engine/export/` (File System Access directory handle, one file per frame) selectable through `canEncode` / `formatFilter`. Interim: video formats only in the dialog, plus the page's ZIP path render as an adjunct (see G2).

**G6 — engine: the render dialog can only be opened from the timeline toolbar.** `installRenderDialog` registers through `registerRenderPopup` and nothing else. A shell that wants "Render…" in the File menu or top bar has no entry. Generic fix: let the popup registry expose an `openRenderPopup()` that any menu item can call. Interim: users open the timeline (T) and press Render.

**G7 — engine: track groups are a hardcoded, fractal-shaped list.** `classifyTrackId` in `utils/groupTracks.ts` knows `julia.*`, `coreMath.*`, `hybridParams.*`, `weave.*` by name and drops everything unknown into "Shading". A new shell's Detail / Colour / Light params would all be filed under Shading. Generic fix: a group registry (`registerTrackGroup(prefixOrPredicate, groupName)`) or a `timelineGroup` field on the feature definition; this also removes the five literal `julia.*` ids from shared code. Interim: name the camera feature `camera` so `camera.u` lands in Camera; accept Shading for the rest.

**G8 — engine: rotation interpolation is decided by substring.** `interpolate` treats any id containing `rot`, `phase` or `twist` as an angle. Generic fix: an explicit registry like `registerLogTrack` (`registerAngleTrack`), or a param-level flag. Interim: name params so only real radian angles contain those substrings (the page's phase angles qualify; check their units before relying on it).

**G9 — engine: `binderRegistry` entries are invisible to the UI.** `list()`, `label` and `category` have no consumer; a registered non-feature value gets no "add track" affordance, no live value and no dirty state. Generic fix: a matching `read: () => number` on `BinderEntry` consumed by `getLiveValue` and the default Key Cam walker, and a track picker that reads `list()`. Interim: back every animated value with a DDFS param (the blueprint does).

**G10 — engine: Key Cam tracks are labelled with their raw id.** The default capture creates `{ label: tid }`, so the row reads `camera.u`. **G12 — renderer: frames are order-dependent through the light rig.** The rig is blended from the previous frame (`'fresh'` on frame 0, then `0.35`).
